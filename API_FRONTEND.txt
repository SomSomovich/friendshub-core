0. ОБЩЕЕ

Аутентификация
--------------------------------------------------------------------------------
Пользовательский API:
    Authorization: Bearer <session_token>
    X-Device-Number: <n>          опционально; если задан, должен
                                  совпадать с device_number сессии,
                                  иначе 403

Bot API:
    X-Bot-Token: <bot_token>      без префикса Bearer


Формат ошибок
--------------------------------------------------------------------------------
Все ошибки — JSON:

    {
      "error": "not_found",
      "message": "not found"
    }

С details (для replenish_required):
    {
      "error": "replenish_required",
      "message": "prekey pool needs replenishing",
      "details": {
        "one_time_available": 2,
        "kyber_one_time_available": 5,
        "minimum_required": 4
      }
    }

Значения error → HTTP статус:
    not_found             404
    unauthorized          401
    forbidden             403
    dm_restricted         403   (получатель не принимает DM от незнакомцев)
    bad_request           400
    conflict              409
    rate_limited          429   (с Retry-After)
    replenish_required    503
    payload_too_large     413
    internal_error        500


Rate limits
--------------------------------------------------------------------------------
Фиксированное окно 60 секунд, если не сказано иное.

    /register                          5    / IP / мин
    /login, /login/2fa                10    / IP / мин
    /2fa/*                            10    / IP / мин
    /account/delete/*                 10    / IP / мин
    /attachments/init                 30    / account / мин
    /accounts/{id}/devices            30    / account / мин
    /accounts/{id}/devices/{n}/bundle 10    / (account, device) / мин
    /handles/*                        60    / account / мин
    /groups/by-handle/{h}             60    / account / мин
    /channels/by-handle/{h}           60    / account / мин
    /search, /contacts/search         30    / account / мин
    typing (WS)                       20    / (account, conversation) / мин

    # Новые write-лимиты
    POST /groups                       5    / account / час
    POST /channels                     5    / account / час
    POST /conversations/{id}/invites  30    / account / час
    POST /contacts                    60    / account / час
    POST /calls                       60    / account / час
    POST /channels/{id}/posts         30    / account / мин
    POST /groups/{id}/members         60    / account / час
    PUT  /profile/username             3    / account / час
    POST /avatars/me                  10    / account / час
    DELETE /groups/{id}               10    / account / час
    DELETE /channels/{id}             10    / account / час
    POST /groups/{id}/owner           10    / account / час
    POST /channels/{id}/owner         10    / account / час

    Bot: /getUpdates                  60    / bot / мин
    Bot: /accounts/{fh}               60    / bot / мин

При превышении:
    HTTP/1.1 429 Too Many Requests
    Retry-After: 42
    { "error": "rate_limited", "message": "rate limited" }


Лимиты квот (не rate limit, а cap)
--------------------------------------------------------------------------------
    Групп на аккаунт                  99
    Каналов на аккаунт                99
    Участников в группе               5000
    Ботов на аккаунт                  20
    Активных устройств на аккаунт     10
    Пина на конверсацию               100  (PINNED_MAX_PER_CONVERSATION)
    OTK на устройство                 200
    Доп. полей в профиле              10   (каждое label ≤64, value ≤128)


Соглашения
--------------------------------------------------------------------------------
- timestamps    — unix-секунды (i64)
- id            — UUID-строки (в WS — 16 байт)
- пагинация     — курсорная, параметры before / limit
- формат        — snake_case

1. AUTH
================================================================================

--------------------------------------------------------------------------------
POST /api/v1/register
--------------------------------------------------------------------------------
Auth: нет
Лимит: 5/IP/мин

Запрос:
    { "password": "correct horse battery staple" }

Ограничения пароля: 8..128 символов.

Ответ 201:
    {
      "id": "<uuid>",
      "user_id": 42,
      "fh_number": "FH1234567",
      "username": "User_1234567"
    }

Ошибки:
    400 — пароль не проходит проверку длины
    429 — rate limit


--------------------------------------------------------------------------------
POST /api/v1/login
--------------------------------------------------------------------------------
Фаза 1: пароль. С включённой 2FA — возвращает challenge.

Auth: нет
Лимит: 10/IP/мин

Запрос:
    {
      "fh_number": "FH1234567",
      "password": "...",
      "device_number": 3
    }

Правила по device_number:
    Любое значение >= 1 принимается. Номер — routing key, не credential.
    Сессия будет привязана к этому номеру. Если номер принадлежит
    активному устройству — сессия для него. Если номер свободен (новый
    или ревокнутый) — сессия для девайса, который сейчас будет
    зарегистрирован (см. POST /devices).

Ответ 200 без 2FA:
    {
      "kind": "session",
      "session_token": "<token>",
      "expires_at": 1772592000
    }

Ответ 200 с 2FA:
    {
      "kind": "totp_required",
      "challenge_token": "<token>",
      "expires_in_seconds": 300
    }

Ошибки:
    400 — device_number < 1
    401 — нет FH, неверный пароль
    429 — per-account lockout или IP rate limit


--------------------------------------------------------------------------------
POST /api/v1/login/2fa
--------------------------------------------------------------------------------
Фаза 2: TOTP или backup-код. Расходует challenge.

Auth: нет
Лимит: 10/IP/мин

Запрос:
    {
      "challenge_token": "<из /login>",
      "code": "123456",
      "device_number": 3
    }

ВАЖНО: challenge одноразовый. Второй POST с тем же токеном → 401.
Клиент должен сбрасывать challenge_token после успеха.

Формат code:
    6 цифр                — TOTP
    A-Z, 2-9 (10 символов) — backup-код (регистр и дефисы не важны)

Ответ 200:
    {
      "kind": "session",
      "session_token": "<token>",
      "expires_at": 1772592000
    }

Ошибки:
    401 — нет/протух/использован challenge, неверный код
    429 — lockout или IP rate limit


--------------------------------------------------------------------------------
POST /api/v1/logout
--------------------------------------------------------------------------------
Отзывает текущую сессию.
Auth: Bearer
Ответ: 204

2FA: enroll / verify / disable
--------------------------------------------------------------------------------

POST /api/v1/2fa/enroll
    Auth: Bearer

    Запрос: {}

    Запрос: { "password": "...", "code": "123456" }
    Ответ: 204
    Ошибки: 401, 409, 429


================================================================================
2. ACCOUNT (УДАЛЕНИЕ)
================================================================================

Двухфазное удаление:
  initiate — создаётся pending-запись (не удаляет).
  confirm  — через 5 минут и в течение 5 минут после: полная повторная
             аутентификация (пароль + TOTP если включён) и hard-delete.
  cancel   — отменяет на любом этапе до confirm.

--------------------------------------------------------------------------------
POST /api/v1/account/delete/initiate
--------------------------------------------------------------------------------
Auth: Bearer
Лимит: 10/IP/мин
Запрос: {}

Ответ 200:
    {
      "confirm_after": 1770000300,
      "confirm_until": 1770000600,
      "confirm_after_seconds": 300,
      "confirm_window_seconds": 300
    }


--------------------------------------------------------------------------------
POST /api/v1/account/delete/confirm
--------------------------------------------------------------------------------
Auth: Bearer
Лимит: 10/IP/мин

Запрос:
    {
      "password": "...",
      "code": "123456"     // обязателен при 2FA
    }

Ответ: 204 (аккаунт удалён)
Ошибки:
    400 — нет pending-записи, отменена, рано или окно истекло
    401 — неверный пароль/код
    409 — окно ещё не открылось / уже закрылось
    429 — lockout


--------------------------------------------------------------------------------
POST /api/v1/account/delete/cancel
--------------------------------------------------------------------------------
Auth: Bearer
Ответ: 204
Ошибки: 404


--------------------------------------------------------------------------------
GET /api/v1/account/delete/status
--------------------------------------------------------------------------------
Auth: Bearer

Ответ 200 (pending):
    {
      "pending": true,
      "account_id": "<uuid>",
      "initiated_at": 1770000000,
      "confirm_after": 1770000300,
      "confirm_until": 1770000600
    }

Ответ 200 (нет):
    {
      "pending": false,
      "account_id": null,
      "initiated_at": null,
      "confirm_after": null,
      "confirm_until": null
    }

Побочный эффект: presence broadcast всем, кто тебя видит.

================================================================================
4.4 DM policy
================================================================================
Кто может открыть direct-конверсацию с тобой.

Значения:
    "everyone"       — любой может писать (дефолт)
    "contacts_only"  — только те, у кого уже есть общая peer-конверсация
                       (direct или group). Проверка на аккаунт, не на
                       устройство: если ты уже общался с этим человеком
                       с любого девайса — он не "новый", и с нового
                       устройства того же человека тоже может писать.

При "contacts_only" чужой аккаунт при попытке получить prekey bundle
получает 403 с error="dm_restricted".

--------------------------------------------------------------------------------
GET /api/v1/profile/dm-policy
--------------------------------------------------------------------------------
Ответ 200: { "policy": "everyone" }


--------------------------------------------------------------------------------
PUT /api/v1/profile/dm-policy
--------------------------------------------------------------------------------
Запрос: { "policy": "contacts_only" }
Ответ: 204
Ошибки: 400 — неверное значение

    - У каждого твоего отправленного сообщения есть server_timestamp
      (приходит в Receipt после EnvelopeUpload, см. раздел 30).
    - Для каждого участника B: если B.last_read_at >= server_timestamp
      твоего сообщения — прочитано B.
    - Live через WS ServerFrame::ReadReceipt.

23. SEARCH
================================================================================

--------------------------------------------------------------------------------
GET /api/v1/search
--------------------------------------------------------------------------------
Глобальный поиск.

Лимит: 30/account/мин

Query:
    q       (обязательно)  3..64 символа
    scope   (опционально)  "identifiers" (дефолт) | "all"
    limit   (опционально)  1..50, дефолт 20

scope=identifiers:
    FH-номер аккаунта + handle групп/каналов/ботов.
scope=all:
    username, FH-номер, title групп/каналов, handle_display, handle.

Матчинг: pg_trgm similarity. Перестановка символов, лишний/пропущенный
символ — находятся.

    {
      "results": [
        {
          "entity_type":  "account" | "group" | "channel" | "bot",
          "entity_id":    "<uuid>",
          "display_name": "User_1234567",
          "identifier":   "FH1234567",
          "avatar_url":   "/avatars/<uuid>"
        }
      ]
    }

Поля по типу:
    account — display_name = username, identifier = fh_number,
              avatar_url = /avatars/{account_id}
    group   — display_name = title, identifier = handle (nullable),
              avatar_url = /conversations/{id}/avatar (nullable)
    channel — то же
    bot     — display_name = handle_display, identifier = handle_normalized,
              avatar_url = null

Блокировки игнорируются. Пагинации нет.
Ошибки: 400, 429

      kind: Hello {
        session_token:     "<из /login>",
        device_number:     <n>,     // должен совпадать с сессией
        client_name:       "friendshub-web",
        client_version:    "1.0",
        protocol_major:    0, protocol_minor: 1, protocol_patch: 0
      }
    }

2. Server → Client:
    ServerFrame {
      kind: Hello {
        session_id: "<uuid>",
        account_id: <16 bytes>,
        device_number: <n>,
        server_timestamp: <unix>,
        protocol_major: 0, protocol_minor: 1, protocol_patch: 0
      }
    }

3. Backlog:
    ServerFrame {
      kind: Delivery {
        envelopes: [ Envelope, ... ]
      }
    }


ClientFrame kind's
--------------------------------------------------------------------------------
    ClientHello       hello            только один раз, в начале
    Ping              ping             { client_timestamp }
    EnvelopeUpload    upload           { envelopes: [Envelope] } до 128
    EnvelopeAck       ack              { envelope_ids }
    TypingFrame       typing           { conversation_id }
    HistoryRequest    history_request  { target_device_number, conversation_ids }


ServerFrame kind's
--------------------------------------------------------------------------------
    ServerHello              hello             после handshake
    EnvelopeDelivery         delivery          { envelopes: [...] }
    EnvelopeAck              receipt           { envelope_ids, server_timestamps }
    Pong                     pong              { client_timestamp, server_timestamp }
    ErrorFrame               error             { code, message, fatal }
    PresenceUpdate           presence          { account_id, is_online, last_seen, ... }
    BotMessageDelivery       bot_message       { ... }
    ChannelPostDelivery      channel_post      { ... }
    TypingDelivery           typing            { conversation_id, account_id }
    ReadReceiptDelivery      read_receipt      { conversation_id, account_id, last_read_at }
    ConversationUpdatedDelivery  conversation_updated
                                                 { conversation_id, title, description,
                                                   is_public, members_changed }
    HistoryRequestRelay      history_request_relay
                                                 { from_device_number, conversation_ids }


Отправка сообщений (EnvelopeUpload)
--------------------------------------------------------------------------------
ClientFrame {
  kind: Upload {
    envelopes: [
      {
        envelope_id:              <16 bytes>,
        sender_account_id:        <16 bytes>,
        sender_device_number:     <n>,
        recipient_account_id:     <16 bytes>,
        recipient_device_number:  <n>,
        envelope_type:            <1..15>,
        is_prekey_message:        true | false,
        ciphertext:               <bytes, <= 64 KiB>,
        client_timestamp:         <unix>,
        conversation_id:          <16 bytes>    // пусто = "не в чате"
      }
    ]
  }
}

Ограничения:
    до 128 конвертов в одном Upload
    ciphertext <= 64 KiB
    envelope_type в 1..=15
    sender_account_id = твой
    recipient_device существует и не revoked
    recipients с блокировкой в любую сторону — дропаются молча
    conversation_id: ты должен быть участником; иначе поле обнуляется

EnvelopeType (proto):
    1  MESSAGE
    2  SYNC
    3  SENDER_KEY
    4  EDIT
    5  DELETE
    6  REACTION
    7  READ_RECEIPT       (envelope, не WS-фрейм)
    8  TYPING             (через envelope ОТВЕРГАЕТСЯ)
    9  ATTACHMENT_KEY
    10 CALL_OFFER
    11 CALL_ANSWER
    12 CALL_ICE
    13 CALL_HANGUP
    14 CALL_REJECT
    15 BOT_MESSAGE
    16, 17 — PIN/UNPIN — УДАЛЕНЫ из enum, зарезервированы


Подтверждение (Receipt)
--------------------------------------------------------------------------------
ServerFrame {
  kind: Receipt {
    envelope_ids:      [<16 bytes>, ...],
    server_timestamps: [<i64>, ...],   // параллельно ids
  }
}

Контракт:
    - server_timestamps одной длины и порядка с envelope_ids.
    - Все envelope одного upload-батча имеют ОДИН server_timestamp.
    - Receipt приходит и для повторно отправленных envelope.
    - Клиент сохраняет для каждого сообщения: message_id → server_timestamp.


Typing
--------------------------------------------------------------------------------
Клиент → сервер:
    ClientFrame { kind: Typing { conversation_id: <16 bytes> } }

Сервер → получателям (кроме отправителя):
    ServerFrame { kind: Typing { conversation_id, account_id } }

Правила:
    - Клиент шлёт не чаще раза в 3 секунды, пока идёт ввод.
    - Никакого "stop" — индикатор сам истечёт через 5 секунд.
    - Для channel/saved не рассылается.
    - Для group с member_count > TYPING_MAX_GROUP_MEMBERS не рассылается.
    - Rate limit: 20/мин на (account, conversation).
    - Не сохраняется.
    - ENVELOPE_TYPE_TYPING через EnvelopeUpload отвергается.


Read Receipt
--------------------------------------------------------------------------------
ServerFrame { kind: ReadReceipt { conversation_id, account_id, last_read_at } }

Приходит всем участникам, кроме сделавшего POST /read. Включая
остальные устройства того же account.
Приходит ТОЛЬКО когда read marker реально сдвинулся.


ConversationUpdated
--------------------------------------------------------------------------------
ServerFrame {
  kind: ConversationUpdated {
    conversation_id,
    title,          // optional
    description,    // optional
    is_public,      // optional
    members_changed // bool
  }
}

Приходит при изменении метаданных группы/канала или состава участников.
Всегда несёт текущее состояние, не дельту.


History Request (для multi-device sync)
--------------------------------------------------------------------------------
Новое устройство → сервер:
    ClientFrame {
      kind: HistoryRequest {
        target_device_number: <n>,          // старое устройство
        conversation_ids: [<16 bytes>, ...]
      }
    }

Сервер проверяет:
    - target — активное устройство того же аккаунта
    - все conversation_ids — конверсации, где отправитель участник
    - размер списка ≤ 200

Сервер → старому устройству:
    ServerFrame {
      kind: HistoryRequestRelay {
        from_device_number: <n>,
        conversation_ids: [<16 bytes>, ...]
      }
    }

Дальше старое устройство читает локальную БД, перешифровывает под сессии
нового и шлёт обычным EnvelopeUpload на (recipient_account_id = свой,
recipient_device_number = target).

Если target не онлайн — сервер возвращает ErrorFrame с "not connected".


Доставка (Delivery)
--------------------------------------------------------------------------------
ServerFrame { kind: Delivery { envelopes: [ Envelope, ... ] } }

Приходит:
    - live, если получатель онлайн
    - в backlog при WS-подключении
    - после reconnect, если не получил ack

Клиент ack'ает:
    ClientFrame { kind: Ack { envelope_ids: [<16 bytes>, ...] } }


Ping/Pong
--------------------------------------------------------------------------------
ClientFrame { kind: Ping { client_timestamp } }
ServerFrame { kind: Pong { client_timestamp, server_timestamp } }


Ошибки WS
--------------------------------------------------------------------------------
ServerFrame::Error { code, message, fatal }

fatal=true — сервер закрывает соединение.
Коды fatal:
    handshake        — нет Hello за 10 сек
    timeout          — то же
    protocol         — несовпадение major
    unauthorized     — нет/протух токен
    device_mismatch  — Hello.device_number != session.device_number
    session_revoked  — сессия отозвана
    device_revoked   — девайс отозван
    replaced         — этот девайс подключился заново
    flood            — флуд
    account_deleted  — аккаунт удалён


Переподключение
--------------------------------------------------------------------------------
1. Backoff: 1s, 2s, 4s, 8s, …, max 30s.
2. При подключении — Hello с тем же session_token.
3. Если fatal (кроме flood) — не переподключаться, идти в /login.
